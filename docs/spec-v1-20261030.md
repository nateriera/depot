# Depot public specification

This document describes the implemented responsibilities and invariants. The
filename is retained for existing references; it contains no private build
chronology. The detailed, as-built contract is [FORMATS](../turntable/FORMATS.md).

## 1. Purpose

Keep bounded coding work, its inputs, its execution, and its evidence together.
The operator should see what is queued, running, waiting, blocked, or completed
without reconstructing state from agent conversations.

## 2. Components

The turntable runs and supervises adapters. A waybill names an item's identity,
track, adapter, budgets, and verification inputs. The floor projects records and
drops operator intents; the daemon lands those intents as records.

## 3. Scope

This is a local Linux tool with a loopback web UI. It is not a multi-user hosted
service. Human review and merging remain explicit responsibilities. Source,
operational records, and optional note directories are separate concerns.

## 4. Record ownership

Use a private records directory. Plain directories work without Git. A Git-backed
yard uses `main` and its own configured origin; the daemon commits records
host-side, pulls fast-forward changes, and pushes records. Adapters build work
in their own workspaces and never own the yard's records commits.

## 5. Event spine

Item events append to the item log and global log. Track lifecycle events append
only to their per-track log. Card and track state are derived by reading these
spines. Waybill status is a derived cache, not a replacement for events. A
message annotates work; it does not move a completed card or approve a run.

## 6. Work and return path

Filing creates Queued work. An explicit approval authorizes a dispatch. The host
checks the exact expected changed-file set and reruns the specified tests. Only
passing verification produces a host-side work commit. Repository work is pushed
to its named review branch; protected delivery branches are refused. A human
controls review and merge. Completion is recorded by a passing `reviewed` event
through the review integration, not inferred from a model report or Git push.

## 7. Supervision

Each run records adapter/model/posture, timestamps, exit status, and usage when
available. Heartbeats record elapsed time and adapter-quiet age. A visible
`stalled?` mark is an observation; it does not itself kill or restart a process.
The wall-clock timeout is the mechanical run limit. Failures remain evidence.

## 8. Floor

**Columns = the gate sequence:** Queued → Briefed → Building → Gating → Review → **Awaiting operator** → Interrupted → Done. **Rows = tracks** (projects). **Cards = work items.**
Interrupted is the stage of a stranded run whose completion was not recorded, distinct from a live run; it is not a condition-only marker or a required gate before Done.
Conditions such as blocked, parked, and stalled remain on the card. Selecting a
card opens its context and action panel. Each control states its consequence.
Pending intents remain visually distinct from landed records.

## 9. Questions and messages

A question ends a run and waits for an operator response. Answering and approval
are separate actions. Inputs not yet landed cannot be silently bypassed by an
approval. Messages after a dispatch are carried into the next run; the dispatched
brief is the delivery record. Reopening completed work is a separate explicit act.

## 10. Truth grammar

Claimed means an agent reported it. Recorded means the system observed it.
Verified means an independent check has evidence, with a named checker. An
adjudication is a recorded human override, never a mechanical verification pass.
The presentation must preserve those distinctions.

## 11. Track lifecycle

Active tracks dispatch normally. Paused tracks hold new dispatches. Tabled tracks
leave the main board for its shelf. Ended tracks and all their cards appear in
Archive. End refuses Building/Gating/Review items; otherwise it parks open items
in the same records commit as the track end. Reopen leaves those parked holds
intact. Filing into a tabled track revives it in the creation commit; ended tracks
must first be explicitly reopened. Done-card folding is a browser preference.

## 12. Blocked decisions

The panel shows full verification discrepancies and current-run evidence.
Re-run, recovery of an existing commit for review, and adjudication each require
explicit operator action. Stale run/commit pointers are refused. No automatic
merge, recovery, approval, permission expansion, or verification override occurs.

## 13. Setup and extensions

The service installer targets Linux/systemd user services. Paths, adapter
executables, and port are configurable; note integration is opt-in. The floor
binds only to loopback and its same-origin checks are not authentication.
See [installation](installation.md), [configuration](configuration.md), and the
fictional demo's [legibility checks](legibility-tests.md).
